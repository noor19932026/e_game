# e_game · 合并学单词

独立的网页版英语小店游戏。主线为“帮 Mia 准备野餐”：学习 bread、apple、milk、water，完成数量订单和装包指令。自由合成扩展为 11 个生活主题、78 个物品词、67 条动作关联、22 个常用搭配；每条路线 6～8 级。

公网试玩：[https://polanking.com/e-game/word-merge/](https://polanking.com/e-game/word-merge/)。2026-10-15 已发布游戏代码版本 `a3ccae6`，包含野餐章节、简化界面、动物来访和小店装扮。本地与公网完整浏览器验收、19 项规则测试、嵌套路径静态资源检查均通过；旧版实际浏览器存档升级到版本 4 后仍保留棋盘、星币、订单和练习记录。

2026-10-16 本地迭代：野餐改为同屏点选直接交付；自由合成扩展为 48 格，增加组合配方、成长目标和补给升级。这一轮尚未发布到公网，上述链接仍为 10 月 15 日发布版本。

服务器发布目录为 `/var/www/e-game/word-merge/`。发布前的可读静态备份和回退目录保存在 `/var/www/e-game/backups/`，发布记录保存在 `/var/www/e-game/releases/`。本次切换保留了旧版哈希资源，兼容已打开的浏览器页面。

本项目从 E_Partner 的试玩页独立出来，运行时不依赖 E_Partner，不包含登录、后台 API、数据库、OSS 图片或远程字体。图片均为内置 SVG，英语朗读使用设备的浏览器／系统语音。

## 开发与验证

需要 Node.js 22.12+（建议 24）和 pnpm 11.4.0。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

开发地址为 http://127.0.0.1:5010/。

```sh
pnpm test
pnpm build
pnpm preview
```

生产构建在 `dist/`。本机预览地址为 http://127.0.0.1:5011/。浏览器完整验收需 Python Playwright 与 Chromium，在预览服务启动后执行 `pnpm test:browser`。`pnpm preview` 仅用于本机验收，生产使用静态网站服务或 Nginx。

## 游戏与内容

界面分为“今日任务、自由合成、生活小镇、学习、我的小店”五个入口，一次只展示当前功能。“生活小镇”内进入接客、厨房、小屋、送货、钓鱼、照料、农场与寻宝解谜，支持生活日常／户外探索分类；“学习”内切换隔天复习、图鉴与课堂，单词动作链按需展开。刷新保留当前入口，游戏进度仍使用原有存档。完成野餐后，从无锚点链接重新进入会先看到当天来访的小伙伴。

三个街区分别保留 6 列×8 行（48 格）棋盘：花园小店（咖啡、花园、烘焙、早餐）、手作街角（衣物、纸艺、陶艺、学校）、阳光集市（果汁、薯片厨房、水果）。新增内容优先覆盖 egg、apple、pencil、hat、shoes、desk 等常用生活词；较专业的旧词条保持原意。首次合出新词只显示轻提示，继续合成无需答题；顾客订单有物品就可直接交付，避免每单打断合成。小店课堂每轮连续完成 3 题，结束显示本轮小结。首次作答正确记作独立答对；它是练习统计，不代表掌握度。

野餐改成同一屏“看／听请求 → 点食物 → 交付”。一次点击准备一份，两个苹果就点两次苹果；无需单独打开订单、领取两份原料或在第二个棋盘打包。第五步选择把面包放进 bag。每步完成后直接出现下一个请求，食物陆续出现在场景中，最后提供继续自由合成和装扮小店的入口。图文／听力模式、提示标记与间隔复习保留。旧版野餐备餐数据保留在存档里，不作为新流程的门槛。

自由合成的补给一次领取两份，棋盘上方随时可见。每组完成 3／6 单后，补给分别可直接领取第 2／3 级材料，仍可切回基础材料以尝试配方；订单不会要求低于当前补给等级的物品。四个跨材料配方为：咖啡＋面包→咖啡托盘；面包＋水煮蛋→鸡蛋三明治；苹果＋橙子→水果碗；铅笔＋纸→画作。配方材料属于同一个街区，可直接拖动或先后点击来组合。

小店成长会记录合成、首次发现、订单和配方；6 个经营目标发放一次性星币奖励，领取记录持久保存。普通合成奖励 2 星币，组合奖励 5 星币，订单奖励 20 星币。店铺等级由成长经验计算，野餐完成也获得成长。星币与等级都是游戏进度，不代替英语掌握记录。

认识词汇后 24 小时安排复习，使用另一幅 SVG 和新的英语语境。独立通过间隔复习后延长到 3 天；提示后通过则 24 小时后再练，每轮最多连续 4 题。分别记录提示后答对、独立答对和隔天仍答对；主动重新学习会重新安排间隔。提示标记持久保存，刷新不会把提示后完成变成独立答对。复习时间依赖设备时钟，仅为本地练习。

野餐每步奖励 12 星币，完成章节额外奖励 20 星币。首单解锁雨棚，完成章节解锁招牌和花盆；4 款装饰可用星币购买并切换，在“我的小店”中与商品相邻的预览里即时呈现；手机购买后会直接带到预览位置。默认雨棚为原木色，与鼠尾草绿区分。装饰解锁不要求满分。

词库与链长：`src/features/wordMerge/catalog.ts`；追加内容在 `expansion.ts`，原有 35 个词条 ID 含义不变。
成长规则：`src/features/wordMerge/progress.ts`。
棋盘与旧版存档迁移：`src/features/wordMerge/game.ts`。当前存档版本 9，沿用 `epartner-word-merge-v1` 键，自动迁移版本 1、2、3、4、5、6、7、8，旧 5×5 棋盘按原行列扩展到 6×8，保留物品、星币、订单、装饰、来访和旧练习记录；不会将旧答题次数冒充隔天记忆记录。
野餐内容、学习间隔与经营规则：`src/features/wordMerge/journey.ts`。
野餐主界面与两套食物图：`src/components/word/PicnicJourney.vue`、`PicnicArt.vue`。
原创图：`src/components/word/WordMergeArt.vue`。
页面：`src/views/WordMergeGame.vue`。

后续小游戏功能以这个仓库为准，避免同时维护两份源代码；E_Partner 可用入口链接或 iframe 接入独立页面。新增图片与词库时需配套检查链条关系、英中例句、答案唯一性和旧词条 ID 的稳定性。

## 生活小镇：厨房与小屋

2026-10-17 本地新增“生活小镇”入口（`#town`），把原有“开店接客”（`#stores`）、“小小厨房”（`#kitchen`）和“整理小屋”（`#room`）收在同一张小镇地图，顶部仍保留五个入口。这一轮尚未发布到公网。

小小厨房有 12 道菜谱，按英语步骤制作鸡蛋三明治、水果杯、早餐盘、蔬菜三明治、芝士吐司、蜂蜜香蕉吐司、田园沙拉、香橙水果杯、水果串、生菜鸡蛋卷、草莓柠檬水和水果牛奶杯。玩家选择食材、使用工具、组装餐点，桌面上的成品随步骤变化，最后亲手端给顾客。误选不会清空已完成步骤；交付后结算星币、成长与订单，重复点交付不会重复奖励。完成后可迎接下一轮，菜谱收藏和当前步骤持续保存。

整理小屋先拆开搬家纸箱，再按指令选择物品并点目的地，练习 on、in、under、beside 等方位。九组生活场景、36 个摆放任务逐步解锁；正确摆好的物品留在房间中，选错物品或放错位置可重试。每间房完成时发放一次星币和成长，重访已完成房间不会重复领奖。

两种游戏各自保存图文、阅读、听力难度。阅读档只给英文指令；听力档隐藏指令文字和目标图示，点击喇叭重听；图文档与主动提示帮助理解。中途换档、查看提示后的完成单独记录，刷新不清除提示状态，也不把操作次数当成英语掌握度。使用浏览器／系统英语语音，失败时提示主动查看帮助，不自动露出听力答案。

v6 存档迁移至 v7 后，接客轮次、混排商品堆、未交付购物篮、星币、成长、装扮、合成棋盘和学习记录完整保留，并补入两种新游戏的初始进度。新规则在 `kitchen.ts` 和 `room.ts`，界面为 `LittleKitchen.vue`、`TidyRoom.vue`，小镇地图为 `LifeTown.vue`。图片全部为内置 SVG。

## 小镇扩展：送货、钓鱼、照料、农场、寻宝与解谜

小镇新增五个活动入口、六种玩法：

- `#delivery` 小镇送货员：在固定朝北的小镇地图上领取包裹，根据英语方向指令移动并送达。
- `#fishing` 英语钓鱼：观察游动的鱼，根据颜色、大小等英语描述钓取目标，积累鱼图鉴。
- `#care` 宠物照料站：理解口渴、脏爪子、疲倦等需求，选择照料工具并对动物使用，留下添水、清洁与休息的场景变化。与原有合成喂食的动物来访分别保存。
- `#farm` 农场花园：选择种子，在田块中种植、浇水、照料生长并采收，配齐任务所需的收获。生长依靠操作，不要求等待现实时间。
- `#adventure` 寻宝与解谜：场景寻宝通过描述寻找物品、收集线索；轻量解谜使用背包物品与场景互动，完成先取物再开门、修桥等任务链。

五个活动统一使用 `ActivityPrompt.vue` 与 `activity.ts`：默认阅读，听力档隐藏文字和目标提示；图文入门及主动提示会记录帮助，中途切换难度也不计作无提示完成。语音依赖浏览器／系统，失败时提示主动使用帮助，不自动显示听力答案。各游戏分别保存进行中的步骤、道具、收获、收藏和奖励记录；完成任务才结算星币与成长，同一次完成不会因重复点击再次发奖。

地图以生活／户外分类展示八个活动入口，手机为双列卡片，进入活动后用原生选择框切换；顶部仍为五个入口。规则对应 `delivery.ts`、`fishing.ts`、`care.ts`、`farm.ts`、`adventure.ts`。v7 升级 v8 时完整保留厨房半成品、小屋摆放、接客购物篮、旧棋盘和学习记录，补入新增游戏的初始状态。本轮仍为本地开发版，尚未发布公网。

## 开店接客

`#stores` 为独立找货配套玩法，三家店免费开放：街角超市按清单配购物袋；水果市场凑三份同类或混装水果篮；服装店看懂颜色，搭配衣帽鞋。三家店共 44 种商品（含 8 种衣物颜色），每店 18 组清单、共 54 组，每轮 3 位顾客，连续 6 轮后再循环。

商品分散混排在同一堆里，有限六格购物篮一次拿一件；可随时放回，配齐一位顾客的数量后整套交付，只消耗该套商品，其他物品留在篮里。每轮库存覆盖全部订单并有干扰商品，不设置倒计时、失败扣款或重新合成门槛。三单完成后显示结算，再主动开始下一轮。每单获得 `12 + 商品件数 × 4` 星币及 8 成长，并计入小店经营的交付目标；重复点击不重复奖励。

接单难度有三档，默认“阅读接单”：顾客只有英文句子与文字清单，商品堆只显示图片；“听力接单”隐藏顾客句子、文字清单和篮子里的需求摘要，只通过喇叭播放请求；“图文入门”保留图片与英文配对。三档均可主动打开图文／中文提示，提示后或本轮中途切换难度的交付单独记录；不把找货次数计入独立回忆。难度偏好单独保存在 `epartner-store-request-mode`，刷新或切页不会把听力模式变回可见文字；此偏好与游戏进度分别保存。语音不可用时给出明确反馈，玩家可主动切换或查看提示。切店、切导航和刷新保留每店轮次、商品堆、购物篮和交付情况。v5 存档保留全部旧进度并补入三家新店；v1–v4 仍按原规则迁移。

规则与商品：`src/features/wordMerge/stores.ts`；界面与内置 SVG：`StoreCounter.vue`、`StoreProductArt.vue`。参考用户描述的“从一堆商品里找出顾客要的东西”设计，未确认与“火锅捞”同名小程序的官方玩法或实现一致。

## 小动物来访

“今日任务”内选择小伙伴的来访卡，进入动物备餐。猫 Mochi、狗 Biscuit、兔子 Clover、虎皮鹦鹉 Pip 免费轮换：每次完整打开或刷新页面产生一位新访客，每四次来访覆盖四类动物，相邻来访不会重复；切换游戏导航不会刷新访客。跨本地自然日也会迎来新访客。动物会出现在装扮商店的小店插画旁。

每种动物有“原料小份 → 一碗／篮／碟 → 野餐盒”三层备餐路线。免费补给、点选合成、选中匹配英语请求的餐点后招待；首次招待展开对应野餐盒层级。物品与英语词义固定，不与旧词条 ID 混用。动物备餐是独立 8 格棋盘，支持退回选中物品，换访客仍保留备餐。

招待后点动物互动，发现隐藏添水委托；听懂 water、选中清水，解锁可实际合成的“温柔照料”路线：cloth → soft towel → pet cushion。每次成功招待或隐藏委托增加 1 友好积分；每种动物每天首次招待奖励 12 星币，首次隐藏委托奖励 8 星币。重复来访可继续陪伴和积累友好积分，不重复发放当天该物种的星币谢礼。此记录不计为单词独立回忆或掌握度。

食物提示依据 [RSPCA 猫饮食建议](https://www.rspca.org.uk/adviceandwelfare/pets/cats/diet)、[狗饮食建议](https://www.rspca.org.uk/adviceandwelfare/pets/dogs/diet)、[兔饮食建议](https://www.rspca.org.uk/adviceandwelfare/pets/rabbits/diet)与[鸟饮食建议](https://www.rspca.org.uk/adviceandwelfare/pets/birds/diet)编写：游戏为猫、狗和虎皮鹦鹉提供各自的适用品种配方粮，兔子路线围绕干草；水为隐藏任务的正确选择。游戏中的合并层级用于备餐与手作表现，不代表真实喂养份量或配方。

来访与配方规则：`src/features/wordMerge/visitors.ts`。动物／餐点插画与活动界面：`AnimalArt.vue`、`PetFoodArt.vue`、`VisitorCafe.vue`。雨棚、招牌、花盆商品插画在 `DecorationArt.vue`；均为本地 SVG。

## 部署方案一：现有 E_Partner 服务器

使用独立目录 `/var/www/e-game/word-merge/`，保留原站点 `/var/www/e_partner/`。无需部署或启动任何 Python、Node 后台，不涉及数据库。

1. 在开发机或构建器执行 `pnpm install --frozen-lockfile && pnpm test && pnpm build`。
2. 将 **dist 内的全部文件** 上传到独立目录 `/var/www/e-game/word-merge/`。不要只上传 index.html，也不要上传整个源码仓库到站点目录。
3. 备份当前站点 Nginx 配置，在对应域名的 `server { ... }` 内引用 `deploy/nginx-existing-site.inc` 的 location 配置。若 HTTP 自动跳 HTTPS，需要加入实际提供 HTTPS 的 server 块。
4. 用 `nginx -t` 验证配置。验证成功后仅 reload Nginx，然后通过现有域名的 `/e-game/word-merge/` 打开。

Nginx 片段匹配独立目录，不覆盖原站点的 `/api` 和其他页面。旧 `/word-merge/` 入口及资源地址会重定向到新路径，继续兼容已分享的链接。构建的资源使用相对路径，可同时部署在域名根目录或 `/e-game/word-merge/`。

平台／部署面板若支持静态站点：构建命令 `pnpm install --frozen-lockfile && pnpm build`，发布目录 `dist`，无需环境变量、数据库或业务端口。

## 部署方案二：GitHub 仓库 + Docker 构建器

构建上下文为仓库根目录，Dockerfile 为根目录的 `Dockerfile`。构建阶段使用 Node；运行阶段只使用 Nginx，容器端口为 **80**，健康检查路径 `/healthz`。

```sh
docker build -t e-game:latest .
docker run -d --name e-game --restart unless-stopped -p 127.0.0.1:8088:80 e-game:latest
```

以上端口只供服务器本机反向代理。部署面板可把单独子域名转发到此容器的 80 端口；不要停止原 E_Partner 服务来占用它的端口。

服务器直放静态文件时，发布只需要 dist；Docker 和 Node 构建工具不会成为浏览器依赖。

## 试用与反馈

此版本未加入在线统计或自动反馈上报。可让试用者通过原有联系方式反馈：设备／浏览器、体验的主题、遇到的具体步骤，以及截图。不要把个人信息、浏览器存档或账号凭据提交到公开 GitHub Issues。

当前公网域名的 Cloudflare 层会加入现有的 Web Analytics 访问统计。该脚本不是小游戏源码的一部分；小游戏在阻止它加载的浏览器验收中仍可合并、保存和答题。游戏自身没有请求 E_Partner 的 `/api/`，也不依赖 OSS 图片。

游戏进度仅保存在访问者的浏览器内，不跨设备同步，也不写入正式学习记录。换域名或浏览器会使用另一份存档；清除浏览器数据会丢失本地进度。同一浏览器的使用者共用存档。
